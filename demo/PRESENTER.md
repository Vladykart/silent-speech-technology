# Recognition console presenter walkthrough (3–5 minutes)

## 0:00–0:35 — Start with the truth

> “Before I touch anything: this is a concept and simulated pipeline. Every trace, feature, token, candidate, score, threshold, and timing value is authored. There are no electrodes, recordings, biometrics, trained model, live inference, or project accuracy behind this page.”

Point to the temporary-demo banner, **CONCEPT / SIMULATED**, and “Not project evidence.” Do **not** mouth a phrase; that would imply the page sensed you.

> “It runs entirely from bundled files. There is no capture, storage, telemetry, account, or runtime network request.”

## 0:35–1:30 — Clear low-consequence path

Choose **Unlock concept**, then **Play to human gate**.

> “The future research path we are visualizing is multi-channel surface EMG, preprocessing and features, sequence decoding with CTC-style alternatives, abstention, and a human gate. Here the eight traces and every downstream value are synthetic constants. Stage timing is presentation design—not measured latency.”

At the gate, point to candidates and `0.84`.

> “That number is a scripted fixture score, not 84 percent accuracy or a calibrated probability. Clearing the authored threshold still authorizes nothing.”

Choose **Confirm candidate**.

> “Only explicit confirmation moves the simulated text counter. Raw fixture stays zero. This is local page state; no transmission or external action occurred.”

## 1:30–2:35 — Ambiguity, abstention, repair

Press `2`, then **Play to human gate**.

> “This scenario is designed to fail. The top authored score is `0.54`, below the illustrative `0.72` rule, so the interaction abstains and stages no output.”

Choose **Choose authored repair**.

> “This repair is manually authored, not a second prediction. It represents switching to a clear fallback. The repair is still blocked behind confirmation.”

Choose **Confirm candidate** or reject it.

> “Repair and rejection are first-class states. A real study would have to measure their burden and failure distribution; this project has not done that.”

## 2:35–3:20 — Safety-sensitive state change

Press `3`, then **Play to human gate**.

> “The third fixture represents a state-changing cancellation. Even with a high scripted score, it cannot pass without explicit confirmation. Turning the confirmation policy off blocks the action; it never bypasses the gate.”

Prefer **Reject candidate** when closing on low consequence and fallback. If you confirm for demonstration, immediately state that only a simulated local counter changed.

> “This is not safety monitoring or safety automation. It is an interaction pattern showing why state-changing commands need stronger policy.”

## 3:20–4:20 — Source and prerequisites

Scroll to **Source lineage**.

> “Our primary technical reference is David Gaddy’s open research repository at the exact commit shown. Its code path uses recorded facial EMG, signal processing, an eight-channel convolutional path, a Transformer sequence encoder, and character CTC decoding with a language model. We borrowed the explanatory shape, not the implementation.”

> “The upstream README reports approximately 36 percent word error rate in its historical open-vocabulary research evaluation. That is their result, under their conditions—not reproduced here and not our performance.”

Point to **Prerequisites absent here**.

> “Real work requires consented hardware and study data, trained weights, alignments and language-model assets, calibration, participant/session evaluation, complete latency, safety, and governance. None is in this repository.”

## 4:20–4:50 — Close

> “The supportable result today is a deployment-ready static interaction artifact for a low-consequence command-channel thesis. It makes abstention, repair, confirmation, egress state, and evidence boundaries inspectable. It does not demonstrate recognition.”

## Never say

- “It reads thoughts,” “hears inner speech,” “recognized me,” “the model heard that,” or “live inference.”
- “84% accurate,” “91% confidence,” or any interpretation of fixture values as measured/calibrated performance.
- “Real-time” based on authored milliseconds; they are not complete or measured latency.
- “Private,” “secure,” “compliant,” “production-ready recognition,” or “only text leaves” about a device that does not exist.
- Open vocabulary, identity, emotion, medical/AAC readiness, safety monitoring, customer validation, or project accuracy.
- Any diagnosis, user group, customer, pilot, partner, traction, approval, or deployment as established fact.
